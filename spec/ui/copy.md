# 共用文案（2.0.0）

> 两套皮肤共用的文字以本文件为准，各实现逐字使用。皮肤专属的点缀文字（诗句、英文小标、装饰性标签）不在此列，由皮肤自定。
> 测试不依赖这些文案（见 `testids.md`），统一它们是为了「外部一致」：同一个操作在任何实现、任何皮肤下说的是同一句话。

---

## 1. 创建页

**校验提示**

| 键 | 文案 |
|---|---|
| `title` | 先给这枚胶囊起个标题 |
| `content` | 还没写内容呢，写点什么吧 |
| `openMin` | 开启时间至少要在 1 分钟之后 |
| `openMax` | 开启时间不能超过 10 年 |

**封存前的说明**（紧挨着封存控件）

> 封存后，内容和开启时间都不能再修改；可以在「我创建的」里删除。

**封存完成**

- 标题：封存完成
- 复制按钮：复制胶囊码 / 复制链接
- 复制成功提示：已复制胶囊码 / 已复制链接
- 后续入口：查看这枚胶囊 / 再写一枚

## 2. 开启与详情

| 场景 | 文案 |
|---|---|
| 输码格式不对 | 胶囊码是 8 位大写字母与数字 |
| 查不到 | 没有找到这枚胶囊，请核对胶囊码——留意 O 与 0、I 与 1 |
| 详情页查不到（补充一句） | 它也可能已经被作者删除了。 |
| 未开启 | 还没到开启的时候 |
| 倒计时归零 | 时间到了，胶囊正在开启… |
| 「我收藏的」里的未公开胶囊标记 | 未公开 |

## 3. 删除

**按钮**：删除

**确认框**

- 标题：删除这枚胶囊？
- 正文：《{标题}》会被永久删除。持有胶囊码 {code} 的人将无法再打开它，它也会从所有收藏过它的人的列表里消失。
- 警示：此操作不可恢复。
- 按钮：删除（危险色）/ 再想想
- 完成提示：已删除《{标题}》

**「我创建的」页脚说明**

> 胶囊的内容与开启时间封存后不可修改；你可以随时删除自己写的胶囊，无论它是否已经开启。

## 4. 收藏与登录

| 场景 | 文案 |

| 匿名点击收藏 / 创建（确认框标题） | 登录后才能收藏 / 登录后才能写胶囊 |

## 5. 关于页

**它能做什么**（6 项，顺序固定）

| # | 标题 | 说明 |
|---|---|---|
| 1 | 账号与头像 | 邮箱注册即登录；十个内置头像，昵称全站唯一。 |
| 2 | 写一枚胶囊 | 标题、正文、开启时间；没有头绪时，AI 给灵感，也能代笔。 |
| 3 | 倒计时与自动开启 | 没到时间只显示倒计时；归零的那一刻，胶囊自己打开。 |
| 4 | 胶囊广场 | 公开的胶囊陈列在这里，可搜索、筛选，按最新或最热排序。 |
| 5 | 收藏与「我的」 | 收藏任何一枚胶囊，等它开启；在「我的」里管理写过的每一枚。 |
| 6 | 两套皮肤，昼夜两色 | 「时笺」与「琥珀」随时切换，各有明暗两套主题，并记住你的选择。 |

**四条原则**（标题下的引言：这个仓库为什么长成现在的样子。）

| # | 标题 | 说明 |
|---|---|---|
| 1 | 规范即唯一事实源 | 业务契约放在 `spec/` 下：OpenAPI、数据库 schema、设计令牌。代码只是规范的投影，有歧义先改规范。 |
| 2 | 栈内地道 | Signals、组合式、Hooks、Runes、Compose……每个实现都用自己技术栈的惯用写法，而不是把同一份代码翻译十遍。 |
| 3 | 外部一致 | 无论内部怎么写，对外的路由、JSON 形状、错误码与界面必须一致——肉眼可比，才谈得上对比。 |
| 4 | 黑盒验证 | 契约用例与 UI 冒烟都从外部跑，不信任任何实现的自述；每个后端都要在 PostgreSQL 与 SQLite 上各过一遍。 |

**技术栈**：只列本实现（前端 + 当前后端，或全栈自身），不列其他实现。
