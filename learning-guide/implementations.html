二十个实现，逐一详解

每张卡片含技术栈、一句话定位、亮点、取舍与评审打分。打分整理自 docs/backend-review.md / frontend-review.md / fullstack-review.md（满分 100：契约一致性 30 + 技术特色 25 + 代码简洁 20 + 文档 15 + 工程化 10）。

每张卡片底部的 「阅读详解」 链接通往该栈的独立详解页——从各自的 TECHNICAL_GUIDE.md 展开，含整体地图、分层架构、核心机制深读（配图）、从真实请求读代码、招牌坑与改动指南。

评分总览

分差很小是事实而非和稀泥：各栈底子几乎一样好。区分度主要落在「技术特色展示」与「工程化」两栏。

10十个后端

FastAPI 参考实现

Python 3.12 · :29010 · SQLAlchemy 2.0

参考实现：async + Pydantic v2 + SQLAlchemy，分层最「标准教科书」，是其余九家的模板与基准。

亮点
  • llm_client.py 是全项目 LLM 客户端金标准（三风格切换 / 瞬时错误重试 / 坏 JSON 不重试 / CF UA 规避）
  • 21 章手册最厚，含「从真实请求读代码」端到端走查 + 「初学者常见困惑」章
  • 自带 986 行 pytest，十家唯一成规模单测，工程化满分
取舍
  • 作为参考实现，「技术特色展示」分天然偏保守（读者已在别处见过同款 async 写法）
94 / 100

Spring Boot

Java 21 · :29000 · Spring Data JPA

企业级全家桶，约定优于配置，抽象层最厚；controller→service→repository→entity 与四层映射最贴合。

亮点
  • 跨库用自定义 @JdbcType + 自实现 ValueBinder（连 null 也按方言处理）
  • 真 @Transactional(noRollbackFor) + Flyway 参考脚本，诚实展示生产级做法
  • PG 路径 SELECT … FOR UPDATE 行锁 + 原子计数
取舍
  • 抽象层最厚——平时最省心，跨库时必须下沉到 Hibernate 底层 SPI
92 / 100

Gin

Go 1.22 · :29020 · GORM

极简、显式、无魔法，错误一律 if err != nil，所有控制流摆在明面上。

亮点
  • handler 极薄零隐藏分支：CurrentUser → ShouldBindJSON → service → dto.OK
  • Go 标准布局 cmd/{server,migrate} + internal/{handler,service,…}
  • 「没有任何隐藏控制流」的最佳示范
取舍
  • 代码量最大（3130 行）是 Go 风格的必然——手写 DTO↔model 转换、显式错误传播，「冗长换透明」
91 / 100

NestJS

TypeScript (Node) · :29040 · TypeORM

Angular 式 TS 企业框架，装饰器 + DI + 模块化纵切，结构最规整。

亮点
  • EnvelopeInterceptor + 异常 Filter + Guard，最地道的横切关注点处理
  • 每个 feature 模块 controller/service/dto 自带全套，规整度十家第一
取舍
  • 十家唯一不用事务的实现（收藏计数两条独立语句、refresh 无事务无行锁，注释自陈教学简化）
  • 文件最多、单文件最小，跳转成本最高
89 / 100

Elysia

TypeScript (Bun) · :29030 · 原生 SQL

Bun 原生、函数式、原生 SQL，依赖最少（5 个）、最「贴金属」，代码量最少（1719 行）。

亮点
  • 已重构出内聚的 services/{auth,capsules,plaza,favorites,ai}.ts，十家唯一有「演进痕迹」
  • Bun 内置 SQLite/密码/测试，把样板压到最低，启动链路最短
取舍
  • 类型安全靠自觉（原生 SQL 无编译期列校验）；纯逻辑单测薄
90 / 100

Ktor

Kotlin · :29090 · Exposed DSL

Kotlin 协程 + Exposed DSL + 手动装配，轻量 JVM 的教科书写法。

亮点
  • 手册最适合初学者（明确面向「懂 Kotlin 但没接触过 Ktor/Exposed」的读者）
  • install(...) 显式组合插件，与 Spring 自动装配形成清晰对照
  • CrossDbColumns.kt 自定义列类型，点名「对应 Spring JDBC type / ASP.NET ValueConverter」——跨栈引用范例
取舍
  • 无明显短板；AppComponents 手动维护构造顺序的代价手册已诚实说明
92 / 100

ASP.NET Core

C# 12 · :29050 · EF Core 8

EF Core + 中间件管线 + DI，.NET 现代最小宿主。

亮点
  • 诚实展示 .NET 特有坑并给出解法：禁用 [ApiController] 自动 400 统一 422；HS256 密钥 ≥256 位用 SHA-256 派生；ClockSkew=0 去掉 5 分钟宽限
  • CrossDb.cs 仅 SQLite provider 挂转换器，PG 交给 Npgsql，边界干净
取舍
  • 无原则性问题；与 Ktor 同属「扎实但不抢戏」一档
91 / 100

Vapor

Swift · :29060 · SQLKit 手写 SQL

SwiftNIO 全链路 async throws，actor 串行化 SQLite + 手写 JSON 树控显式 null。

亮点
  • actor 串行化 SQLite：AsyncGate（actor 实现的 FIFO 异步互斥）是 Swift 并发模型的地道展示
  • 手写 JSON 枚举树替代 Codable 合成——因契约要 data/errorCode 为显式 null
  • 独有「目录为何叫 server」踩坑记录（SwiftPM 同名 cyclic dependency）
取舍
  • 冷启动需先 ./build 预热（release 编译数分钟），否则契约脚本就绪窗口超时
91 / 100

Axum

Rust · :29070 · sqlx（不用宏）

Rust 类型系统即正确性：IntoResponse 让「漏接错误」编译不过；自研 Value/Cell 跨库层。

亮点
  • IntoResponse 让错误处理变成类型问题：任何 ? 直接产出契约错误外壳，漏接异常编译不过
  • 自研 Value/Cell 跨库编解码层（cell-driven），SQL 文本完全共享
  • 已删除未使用的 sqlx macros feature，依赖更干净
取舍
  • 无原则性问题；?→$n 替换依赖「SQL 文本不含字面 ?」的约定（手册已声明）
93 / 100

Drogon

C++20 · :29080 · 裸 SQL · 全文本协议

C++20 协程，把「异步析构提交竞态」「catch 不能 co_await」两个真实坑写成必读章节。

亮点
  • 两个 C++ 协程真坑成必读章：异步析构提交竞态（awaitCommit 等提交落地再返回）；catch 里不能 co_await（改「记 flag、try 外 co_await」）
  • third_party/openbsd_bcrypt 来历透明（复制本仓库 nest 的内嵌实现，保留 ISC 版权头）
取舍
  • 构建成本最高：FetchContent 静态链接 drogon 本体，首次编译 4–5 分钟
  • std::regex 不支持 \p{L}，昵称校验对 ≥U+0080 一律放行（略宽）
92 / 100

5五个前端

React 参考实现

React 19 · :7174 · Zustand

「UI 是状态的纯函数」——hooks + 单向数据流，生态最大、心智最主流，其余四栈对齐它。

亮点
  • api/client.ts 注释最完整；CreatePage 的 AI 生成流（空标题回填、竞态序号、StrictMode 防重）是全项目交互最佳示范
  • react-router 7 createBrowserRouter data router + 组件式 AuthGate 守卫
取舍
  • 倒计时逻辑在 CapsuleCard 与 CapsuleDetail 各写一遍（Vue/Svelte 用 composable 抽取更好）
  • 内联 style 用量偏大，与 cy-* 类分工边界模糊
92 / 100

Vue 3 最高分

Vue 3.5 · :7173 · Pinia

「响应式应该是自动的，结构应该是分区的」——Proxy 响应式 + SFC，渐进、平衡。

亮点
  • 执行最干净的一份：useCountdown / useDebouncedRef / useClickOutside composable 抽取得当、带用法示例
  • Pinia setup store + wireAuthApi() 显式接线，并注释「store 必须在 app 创建后才能用」的模块加载顺序坑
取舍
  • 设计文档说 Vue 有 capsule store，实际没有（逻辑在页面内）——文档与实现不符，无行为影响
93 / 100

Angular

Angular 19 · :7175 · NgRx Signal Store

「大型团队需要约定、结构与可治理性」——全家桶 + DI + Signals，约定最强、运行时最重。

亮点
  • 现代 Angular 到位：standalone 组件、signalStore、函数式 CanActivateFn、@for/@if 新控制流、内联模板；总代码最紧凑（2794 行）
  • 唯一做路由级懒加载（loadComponent）、唯一把 fetch 封装成可注入 ApiService
取舍
  • 最大缺口：ApiService 用原生 fetch 逐行复刻 React，砍掉了 Angular 最该展示的 HttpClient + interceptor
  • 曾无单测（已补 vitest 7 例）
85 / 100

Svelte 5

Svelte 5 Runes · :7176 · .svelte.ts 单例

「框架应该在编译期消失」——Runes 让响应式像写普通变量，产物最薄之一。

亮点
  • Svelte 5 特性最「新」最完整：runes class store、.svelte.ts 单例、Snippet children、$effect 守卫、runes 工具
  • TECHNICAL_GUIDE 843 行五家最长，含 Svelte vs React vs Vue 对照表
取舍
  • 曾路由偏离（/capsules/:code + 独有 /plaza/:id，逼验证脚本写实现感知特判）——已收敛到 /c/:code
91 / 100

SolidJS

Solid 1.9 · :7180 · 模块级 createStore

「响应式可以细到单个 DOM 节点」——组件只跑一次，无 VDOM，点对点更新，产物最薄（91 KB）。

亮点
  • 细粒度响应式展示充分：闭包请求序号（注释「为什么不放 store 里——避免多余订阅」），patchPlazaFavorited 定点更新
  • 手册独家内容最多：§14 渲染原理（无 VDOM 更新去哪了）、§17 实测踩坑 FAQ
  • 逻辑层逐字复用 react-ts 的纯 TS，证明业务逻辑与框架彻底解耦
取舍
  • 曾缺顶层 ./test 包装脚本（已补）
90 / 100

5五套全栈

Spring MVC 全栈最高

Java 21 · :7179 · Thymeleaf + HTMX

传统 JVM SSR，用 HTMX 给经典 @Controller + Thymeleaf 补上声明式局部刷新。

亮点
  • 工程成熟度五家之首：全 service 正确 @Transactional（含 noRollbackFor）；SmokeTest 是真正的 HTTP 层集成测试
  • CookieTokenFilter 设计优雅，cookie→Bearer 注入让 SSR fetch 复用同一套控制器
  • 业务地基与 backends/spring-boot 复用，避免双份分叉
取舍
  • 手册对招牌特色 HTMX 曾着墨偏少（已扩写为含属性表 + Turbo 对照）
93 / 100

Rails

Ruby · :7181 · Hotwire (Turbo + Stimulus)

「HTML 本身就是 API，片段就是线缆协议」——Turbo Frame/Stream + Stimulus，客户端 JS 最省。

亮点
  • 最框架地道：12 个职责单一的 Stimulus controller；Turbo 负责导航，JS 只做增强
  • 数据层注释教学价值最高：FavoriteService 事务 + PG 行锁 + 「SQLite 依赖单写事务」差异说明
  • 冒烟直击风险点：固定跨库存储格式不变式（小数秒去尾零、uuid↔hex 往返）
取舍
  • 冒烟只覆盖 CrossDb 纯逻辑，无 HTTP 层用例；run/test 硬编码 homebrew ruby 路径
92 / 100

Next.js

TypeScript · :7177 · App Router + RSC

「服务端和客户端是同一棵树的两种节点」——RSC 是默认，前后端边界模糊到同一棵组件树里。

亮点
  • RSC 不是摆设：广场 / 胶囊详情在服务端直调 service 取数（无 HTTP 往返），孤岛只保留必要交互
  • lib/server/session.ts 用 10 行注释讲清「为什么 Bearer 之外还要 httpOnly cookie」
  • 路由层薄如纸（withApi + zod + service，一个 handler 十几行）
取舍
  • 曾五家唯一无 README（已补）；曾未用 generateMetadata 动态标题（已补）
89 / 100

Nuxt

TypeScript · :7178 · 混合渲染

「渲染方式应该能按路由逐个选」——通用渲染 + routeRules 一行决定 SSR 还是 CSR。

亮点
  • 混合渲染教科书级展示：routeRules 把 /create、/me/** 标成 SPA 孤岛，注释讲透「为什么鉴权页 SSR 有害无益」
  • SSR 数据一致性成熟：useAsyncData 服务端预取 + 登录用户客户端补取纠正 favoritedByMe
  • 服务端与 Next 逐行同构，是「换框架不换业务」最好教材
取舍
  • 曾全站无 <title>（与「SSR 利于 SEO」动机自相矛盾，已修）；用 RouterLink 而非 NuxtLink
87 / 100

Laravel

PHP 8.3 · :7182 · Blade + Alpine.js

「服务端把数据备好、把 HTML 渲完，浏览器只点睛」——前后端边界锐利，Eloquent ORM 为招牌。

亮点
  • Eloquent 重构成色好：Model + 关系 + 自定义 Cast（CrossDbBoolean）+ HasCrossDbKey + lockForUpdate 行锁
  • 手册 §1 是五家中最实事求是的（表格列双入口、无营销腔）
  • vite.config.js 注释解释「JS 为何不走 Vite 构建」——对非常规选择主动给理由
取舍
  • 测试套件曾空转（"No tests found" 却报 passed，已补 12 个 phpunit 单测）
  • 曾保留旧 UI 路由别名（已收敛到 /c/{code}）
86 / 100
最有价值的对照读法：挑同一条链路（如 POST /me/favorites 或 refresh 轮转），在 2–3 家之间并排读——跨库适配看 Spring（@JdbcType）↔ Axum（Value/Cell 枚举）↔ Drogon（纯文本协议）；协程并发看 Ktor（连接池=1）↔ Vapor（AsyncGate actor）↔ Drogon（手写 awaitCommit）。这就是本项目最大的价值：同一道题，二十种母语的解法。
