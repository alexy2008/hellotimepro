1技术选型与设计特色

Vue 3 + Vue Router

Composition API + 细粒度响应式，配合全局守卫与嵌套路由，切换页面无需刷新。

Pinia · setup 风格状态

避开旧版 Vuex，响应式 ref 字段 + 直接突变的 action，符合 Vue 3 心智，也易于在组件外调用。

Vite · 极速 HMR

原生 ESM 热更新，组件状态尽可能保留。

设计令牌 + Tailwind v4

颜色/字号抽离为跨前端通用 CSS 变量，暗/亮主题切换高效。

2入口链路：main.ts → App.vue

const app = createApp(App);
app.use(createPinia());   // 装上状态管理
app.use(router);          // 装上路由
wireAuthApi();            // Pinia 就绪后，把 auth store 注入到 api client
app.mount("#app");
顺序很重要：Pinia 必须在 wireAuthApi() 之前装好，因为后者会调 useAuthStore()，而 store 只有在 Pinia 注册到 app 后才能用。这正是「Vue 不能在模块顶层调 configureApi」的根因（见 §8）。

3响应式 vs 重渲染（最值得记）

ref(initial) 返回 { value }，对 .value 的任何读写都被 Vue 追踪。模板里写 {{ email }} 编译器自动加 .value。.value 是 Vue 3 最显眼的写法，初学者常忘加导致失去响应式。

ReactVue
状态useState(0) → [value, setter]ref(0) → { value }
修改setCount(c + 1)count.value++
重渲染整个组件函数重跑只重跑依赖此变量的 effect/DOM
派生useMemo(..., [deps]) 手动列依赖computed(...) 自动追踪
Vue 是细粒度响应式，不是按组件重渲染。每个响应式变量记录被哪些 effect 读过，变化时只通知这些 effect 重跑。这是响应式模型谱系里「虚拟 DOM 阵营 + 自动 Proxy 追踪」的代表。

4SFC 与模板指令

单文件组件（SFC）一个 .vue 里有三块：<script setup lang="ts">（逻辑，声明的变量自动暴露给模板）、<template>（HTML 模板）、<style scoped>（作用域 CSS）。

指令（v- 前缀）

  • v-if / v-else 条件渲染
  • v-for + :key 列表
  • v-model 双向绑定
  • :x 绑 attribute
  • @click 事件

v-model 是杀手锏

v-model="email" = :value="email" @input="email = $event.target.value"，「绑值 + 监听 input」一次写完，让表单代码极短。@submit.prevent 修饰符等价于先 preventDefault()。

5Composition API 与组合函数

最大价值是逻辑复用：把相关状态 + 副作用打包成普通函数（composable），多个组件复用。useCountdown(active) 的 onUnmounted(stop) 保证组件销毁时清掉定时器——必须在 setup 期间同步调用。

export function useCountdown(active: () => boolean) {
  const now = ref(Date.now());
  function start() { timer = setInterval(() => { now.value = Date.now(); }, 1000); }
  watch(active, (on) => { on ? start() : stop(); }, { immediate: true });
  onUnmounted(stop);
  return { now };
}

三个 composables：useCountdown（响应式 now）、useDebouncedRef（防抖）、useClickOutside（点外关菜单）。对照 React 自定义 Hook：Vue composable 不受「Hook 调用规则」束缚，可以在条件分支里调用，因为响应式追踪基于变量身份而非调用顺序。

6路由与守卫

嵌套路由 + Layout（父给 component: MainLayout，子填 <RouterView/>）。鉴权完全交给 router.beforeEach，把策略写在路由 meta.requiresAuth 上：

router.beforeEach((to) => {
  if (!to.matched.some((r) => r.meta.requiresAuth)) return true;
  const auth = useAuthStore();
  if (auth.user || auth.refreshToken) return true;       // 持 refreshToken 即放行
  return { path: "/login", query: { from: to.fullPath } };
});

比 React 版的 <AuthGate> HOC 更集中、更声明式。只允许有 refreshToken 的用户进入是为了「页面刷新场景」——access token 内存丢了、refresh 还在 localStorage，下次 API 调用自动 refresh。

7状态层 Pinia（setup store）

defineStore(id, setupFn)：里面的 ref 是 state、函数是 action、computed 是 getter，返回的对象决定暴露哪些字段。

最容易踩的坑 —— storeToRefs：直接 const { user } = auth 会丢响应式（解构出普通值，不再追踪）。必须 const { user } = storeToRefs(auth) 把每个状态字段还原成 ref。动作函数可以直接 auth.setTokens(...) 解构。

跨 store 联动：FavoriteButton 收藏成功后直接调 plaza.patchFavorited(...)。序列号守卫：let fetchSeq = 0 是闭包变量（不是 ref，不需要触发 UI），保证只有最新请求能写状态。

8数据层与 wireAuthApi

api/client.ts 与 React 版几乎逐字一致（刻意写成框架无关，方便各前端复用）：通用 request<T> + 自动 refresh（模块级 refreshing 单例去重 + _retry 防死循环）。

与 React 的微妙差异：React 能在模块顶层调 configureApi(...)（Zustand create() 直接返回 hook、无需 app 实例）；Vue 的 Pinia store 必须在 app.use(createPinia()) 之后才能 useXxxStore()——所以包成 wireAuthApi() 在 main.ts 显式触发。这是两套生态的本质差异，也是本实现注释里特别强调的教学点。
