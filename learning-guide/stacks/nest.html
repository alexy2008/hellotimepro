NestJS

Angular 式 TS 企业框架：装饰器 + DI + 模块化「纵切」，把 Express 的随意性与 Spring 的约定性结合，结构最规整。

1技术选型与设计特色

NestJS + TypeScript · 企业级模块化

借助强类型 + 元数据设计 + 强大 DI 容器与高度内聚的模块系统，为 Node 提供企业级、高度可控的架构标准。

TypeORM + 跨库自适应

timestampColumn 等辅助在 PG 与 SQLite 间自动适配类型；schema 由 scripts/db 维护，迁移类保留为表达样例。

class-validator + ValidationPipe

DTO 属性装饰器声明边界，全局 ValidationPipe 拦截非法请求并自动过滤多余字段（whitelist:true）。

管道/守卫/拦截器/过滤器生态

Passport JWT Strategy + Guard 鉴权、Interceptor 统一成功包装、全局 Filter 捕获异常映射成契约错误。

2整体地图与请求流向

请求经中间件 → 守卫（Passport 解析 Bearer → request.user）→ 管道（class-validator 验证 DTO）→ 控制器方法 → 服务层 → TypeORM。返回方向 service 返回 plain 对象，EnvelopeInterceptor 包成 {success,data}；出错任何地方 throw ApiException，ApiExceptionFilter 捕获输出统一错误。

3目录结构：按功能模块「纵切」

与其余九家「横切」（先按技术层切）不同，NestJS 是纵切——先按业务模块切，每个模块自带 controller + service + dto 全套。

backends/nest/src/ ├── main.ts # 注册全局管道/过滤器/拦截器 ├── app.module.ts # 根模块：组合所有功能模块 ├── common/ # ApiException / 装饰器 / Filter / Guard / Interceptor ├── database/ # 动态连接 + column-helpers 跨库列类型 ├── entities/ # TypeORM 实体 ├── auth/ capsules/ plaza/ favorites/ me/ health/ # 每个含 controller+service+dto └── capsule-suggestion/ # AI 生成胶囊内容
与 Spring 的 @ComponentScan 不同，NestJS 不自动扫描文件——必须在 @Module 里显式声明所有 provider 和 controller。这是它比 Spring 更显式的地方。

4NestJS 的四个核心思想

① 模块（Module）

@Module 的 imports（引入其他模块的 exports）/ providers（注册的类，默认单例）/ controllers / exports（对外暴露）。根模块把所有功能模块列在 imports。

② 依赖注入（DI）

基于 reflect-metadata，@Injectable() 标记可注入，构造器注入最推荐。@InjectRepository(User) 是 TypeORM 特殊令牌。

③ 装饰器驱动

@Controller/@Get/@Post/@Body/@Param/@Query/@UseGuards/@HttpCode 都是「标签」，真正干活的是 NestJS 启动时扫描标签构建路由表与注入规则。

④ 管道/守卫/拦截器/过滤器

四种「增强器」是核心扩展点：守卫决定能否通过、管道验证转换参数、拦截器环绕 Handler、过滤器捕获异常。

6TypeORM 与跨库列类型

TypeOrmModule.forRootAsync 注入 ConfigService 后构造连接选项，关键 migrationsRun:false（启动不改 schema）、synchronize:false（绝不在生产开，会删表删列）。

column-helpers.ts 跨库列类型：PG 有原生 timestamptz、SQLite 只有 TEXT。timestampColumn() 在 SQLite 返回 {type:'text', transformer: dateTransformer}、PG 返回 {type:'timestamptz'}。ValueTransformer 在读写时自动执行转换，业务代码始终拿到 Date，感知不到方言差异。这是双库三解法里的「A 类」。

原子计数用 .set({ favoriteCount: () => 'favorite_count + 1' })——箭头函数返回的字符串是 TypeORM「原始 SQL 片段」，实现原子自增而非读-改-写。列表用 innerJoinAndSelect 一次查询拿胶囊 + owner，再批量预加载收藏集合，避免 N+1。

7异常与响应包装

ApiException + Filter

继承内置 HttpException，工厂函数 notFound/conflict/…。@Catch()（无参=捕获所有）的 Filter 处理。class-validator 默认抛 400，spec 要求 422——Filter 识别这种 400 body 并转成 422。

EnvelopeInterceptor

controller 只返回 plain 对象，拦截器用 RxJS next.handle().pipe(map(...)) 套统一外壳；204 No Content 不包装。

8Passport JWT 三层

1
Strategy：PassportStrategy(Strategy) Mixin，jwtFromRequest 从 Bearer 提取，validate(payload) 返回值挂到 request.user
2
Guard：JwtAuthGuard（无效 token 抛 401）vs OptionalJwtGuard（验证失败静默放行，user 为 null）
3
参数装饰器：@CurrentUser() 从 request.user 取出当前用户，避免重复写 req.user

9服务层与 refresh

register 用「预检 + 唯一索引 catch 兜底」处理并发竞态。refresh 检测 revokedAt 非空即重放 → 整族 revoke 后抛 401；正常路径旧 token 标 revoked、复用 familyId 续发。

诚实的教学简化：NestJS service 默认没有事务，这里「revoke 旧 + 新增新」是两步独立操作，存在并发窗口（注释自陈「生产应加事务/行锁」）。这是事务四流派里唯一的「④ 无事务」——契约全过，但「十家事务同构」对它不成立。生产应当用 dataSource.transaction(...) 包住。
