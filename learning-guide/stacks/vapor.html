1技术选型与设计特色

Vapor 4 + SwiftNIO

Swift 服务端事实标准。HTTP 由 SwiftNIO 事件循环承载，路由处理器全是 async throws 函数，async/await 全链路异步。

SQLKit 手写 SQL（不用 Fluent）

schema 由 spec/db 外部管理，SQLite/PG 列表示差异大。参数化 raw SQL + 自建跨库编解码层比 Fluent 模型映射更直接、更可教学。

手写 JWT HS256

签发/校验各约 20 行（swift-crypto 的 HMAC + base64url），省掉 jwt-kit 依赖树。

手工 JSON 树

JSON 枚举替代 Codable 合成——契约要求 data/errorCode/content 输出显式 null，而 Swift 合成 Encodable 对 Optional 走 encodeIfPresent 直接丢键。

目录为什么叫 server：SwiftPM 根包身份取自所在目录名。若包直接放在 backends/vapor/，根包身份 vapor 会与依赖包 vapor 同名，报 cyclic dependency。挪进 server/ 子目录即可。

2整体地图与请求流向

SwiftNIO 事件循环 → 中间件栈 CORSMiddleware → ApiErrorMiddleware（自研，替换 Vapor 默认 ErrorMiddleware，因为它的错误 JSON 不是契约外壳）→ 路由 async 闭包（authContext.required/optional 解析 Bearer、req.content.decode 反序列化）→ Services（async throws，db.transaction { sql in }）→ Repositories → AppDatabase（SQLKit raw SQL + 跨库编解码）。

3Swift / Vapor 的四个关键思想

① 全链路 async/await

handler 是 async throws 闭包，从 handler 一路 await 到数据库，写法同步直观、执行全异步。鉴权是显式第一行 required(req)/optional(req)。

② 用 actor 收纳共享状态

可变状态放进 actor，编译器保证串行访问、无数据竞争。两个 actor：LoginRateLimiter（失败计数）、AsyncGate（SQLite 门闩）。

③ 值类型 struct + 构造注入

AppComponents 手动 new 出仓储 → 服务，除两个 actor 与 AppDatabase 外全是值类型 struct。依赖图集中、源码可见、无运行时扫描。

④ 手工 JSON 枚举树

enum JSON 的 Encodable 对 .null 调 encodeNil() 输出字面 null；也用来解析 LLM 任意 JSON，intValue 宽容取整。

4AsyncGate：actor 实现的 FIFO 门闩（必读）

SQLite 单连接被并发请求争用时，需要一把「异步互斥锁」——但不能用阻塞锁（会卡死 SwiftNIO 的事件循环线程）。AsyncGate 用 actor + CheckedContinuation 实现一把不阻塞线程、先到先得的门闩：

actor AsyncGate {
    private var busy = false
    private var waiters: [CheckedContinuation<Void, Never>] = []
    func acquire() async {
        if !busy { busy = true; return }                      // 空闲：直接拿锁
        await withCheckedContinuation { waiters.append($0) }   // 占用：挂起排队
    }
    func release() {
        if waiters.isEmpty { busy = false }                   // 无人等：释放
        else { waiters.removeFirst().resume() }               // 有人等：FIFO 唤醒队首
    }
}
为什么是 actor：actor 隔离让「检查 busy + 改状态」天然原子。为什么不阻塞：等待者挂起成 continuation 存进数组，事件循环线程立刻空出去干别的，轮到时 resume() 续跑——等价「连接池大小为 1」但用协程挂起代替线程阻塞。为什么 FIFO：removeFirst() 按到达顺序唤醒避免饿死。这与 Ktor 池=1、Axum 池上限 1 解决的是同一个问题。

5手工 JSON 树：为什么不用 Codable 合成

契约用 strict equal 断言 data/errorCode/content 为显式 null，而 Swift 合成的 Encodable 对 Optional 走 encodeIfPresent 直接丢键。所以响应一律用 JSON 枚举手工构造：

enum JSON: Sendable { case null, bool(Bool), int(Int), double(Double),
                      string(String), array([JSON]), object([String: JSON]) }
// .null 的 Encodable 实现调 encodeNil() → 输出字面 null

6跨库值编解码

业务 SQL 只写一份，差异收敛在六个助手里（绑定 uuidValue/dateValue/boolValue；读取 uuid/date/bool）：

列SQLitePostgreSQL
UUID32 位无横线 hex TEXT原生 uuid
时间戳ISO-8601 TEXT：微秒 + +00:00原生 timestamptz
布尔0/1 整数原生 boolean
SQLite 的 TEXT 格式与 Python seed（isoformat()）逐字符兼容，同一格式下字符串比较即时间比较，open_at <= :now 与 ORDER BY created_at 在 TEXT 列上仍正确。这是双库三解法的「C 类 · 一份 SQL + 自建值编解码」。

7事务与一致性

两个原语：db.withSQL { }（无显式事务）、db.transaction { }（BEGIN/COMMIT，异常 ROLLBACK）。SQLite 事务用 BEGIN IMMEDIATE 直接拿写锁。约定：service 公共方法只调一次（门闩不可重入）。

  • 收藏计数：INSERT ... ON CONFLICT DO NOTHING RETURNING 返回行 ⇒ 真插入 ⇒ 原子 +1；没返回 ⇒ 已收藏 ⇒ 回读原值。并发 5 连击不重复计数。
  • refresh 轮转：重用检测命中时先提交家族吊销再抛 401。事务内返回 RefreshOutcome 枚举，throw 放事务外（等价 Spring noRollbackFor，流派 ③）。PG 对 token 行加 FOR UPDATE。
  • login 同手法：密码错时事务内返回 nil（干净提交），出事务后再 recordFailure + 抛 401。

8手写 JWT 与安全

func createAccessToken(user: User) -> String {
    let signingInput = "\(base64url(header)).\(base64url(payload))"
    let mac = HMAC<SHA256>.authenticationCode(for: Data(signingInput.utf8), using: key)
    return "\(signingInput).\(base64url(Data(mac)))"
}

校验顺序：形状（3 段）→ 签名（HMAC.isValidAuthenticationCode，常数时间）→ 解析 payload → exp。过期返回 access_token_expired、其它 invalid_token（契约区分）。bcrypt 用 Vapor 内置 Bcrypt（cost 10），兼容 seed 的 $2b$。refresh token 32 字节随机 → base64url，库里只存 SHA-256 hex。
