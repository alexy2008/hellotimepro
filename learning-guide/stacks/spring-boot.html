1技术选型与设计特色

Spring Boot 3 + IoC/DI

控制反转容器以单例管理 service / controller / repository，自动配置（Auto-Configuration）开箱即用，极大提高企业级装配效率。

Spring Data JPA + 方言自适应

方法名自动解析生成 SQL；针对跨库时间列时区差异自制全局 OffsetDateTimeStringConverter，并用 JPA 悲观锁（PESSIMISTIC_WRITE）保证行级并发一致。

Bean Validation + @RestController

DTO（record）属性贴 @NotBlank/@Size/@Pattern，配合 @Valid 开启边界拦截，声明式路由映射简洁直观。

声明式事务 + 异常拦截（AOP）

基于 AOP 用 @Transactional 无侵入管理事务；@RestControllerAdvice 全局异常处理器把 ApiException 统一转成契约错误响应。

2整体地图与请求流向

请求经内嵌 Tomcat → DispatcherServlet → 按 URL 找到 @RestController 方法 → Bean Validation 校验 @Valid @RequestBody → service（@Transactional）→ repository（Spring Data JPA）→ Hibernate 生成 SQL。返回方向 service 把实体转成 record，控制器用 Envelope.ok(...) 包一层，Jackson 序列化成 JSON。

3目录结构

src/main/java/com/hellotimepro/springboot/ ├── HelloTimeProApplication.java # main 入口，@SpringBootApplication ├── config/{AppProperties,WebConfig}.java # 配置载体 + CORS/静态资源 ├── domain/ # JPA 实体（@Entity） ├── repository/ # Spring Data JPA 仓库接口 ├── service/ # 业务层（@Service / @Transactional） ├── dto/Dtos.java # 请求/响应 record，全部集中一文件 └── web/ # @RestController + 全局异常 + 错误码
@SpringBootApplication = @Configuration + @EnableAutoConfiguration（按 classpath 自动装配 Tomcat/Jackson/Hibernate）+ @ComponentScan（扫描 @Service/@Repository/@RestController 纳入容器）。

4Spring 的三个核心机制

Spring Boot 没有「魔法」，但有三件事是 Java 程序员第一次看 Spring 最易困惑的。看懂它们，后面的注解都是它们的语法糖。

机制一IoC 控制反转 + 构造器注入

@Service 让 Spring 启动时把类实例化成单例放进容器；看到构造函数需要某个依赖，自动从容器找到对应 bean 传进来。好处：测试可传 mock、切换实现不改调用方、依赖关系一目了然。

@Service
public class FavoriteService {
  private final CapsuleRepository capsules;
  public FavoriteService(CapsuleRepository capsules) {  // 由 Spring 注入
    this.capsules = capsules;
  }
}
机制二注解驱动 + 反射

@RestController/@GetMapping/@Valid/@Transactional 本身什么都不做，只是「标签」。真正干活的是 Spring 启动时扫描这些标签并注册行为。看代码时凡是看到注解，默念一句：「这是给 Spring 看的标签，行为在框架那边」。

5机制三 · AOP 代理：@Transactional 为什么能工作

方法上贴了 @Transactional 但代码里没有任何 commit()。Spring 启动时不直接把你写的类放进容器，而是创建一个代理类（运行时生成的子类），重写带注解的方法：

代理.register(req)
↓
txManager.begin()
↓
try { result = 原始.register(req); txManager.commit() }
↓
catch (RuntimeException e) { txManager.rollback(); throw e }
调用方拿到的是代理实例，方法调用自动「被」事务化
常见陷阱：在同一个类内部调用另一个 @Transactional 方法不会走代理（this.foo() 绕开了代理对象），事务不生效。本项目都在「外部进入服务的入口方法」上加注解，避开此坑。

6Web 层与统一外壳

控制器只做「校验 + 取 user + 转 DTO」。统一外壳 Envelope 是一个 record，所有成功返回都 Envelope.ok(...)，错误由 GlobalExceptionHandler 用 ErrorEnvelope 构造。

鉴权：AuthContext

控制器不直接解析 JWT，统一调 auth.required(authorization)（必须登录）或 auth.optional(...)（影响 favoritedByMe）。

刻意不引入 spring-boot-starter-security，只用它的 BCryptPasswordEncoder，让鉴权流程一眼看穿，便于教学。

全局异常：@RestControllerAdvice

跨所有控制器的异常拦截器，按类型路由到 @ExceptionHandler：ApiException / MethodArgumentNotValidException（校验）/ Exception（兜底 500）。业务可放心 throw ApiException.notFound(...)。

7DTO + Bean Validation

整个 DTO 集中写在 Dtos.java，全是 record（自动生成字段/构造/equals/访问器）。注解是 Jakarta Bean Validation 规范，@Valid 触发，失败抛 MethodArgumentNotValidException → 全局处理器转 422 + 逐字段 details。

public record RegisterRequest(
    @NotBlank @Email @Size(max = 254) String email,
    @NotBlank @Size(min = 8, max = 128)
    @Pattern(regexp = "^(?=.*[A-Za-z])(?=.*\\d).{8,128}$") String password,
    @NotBlank @Size(min = 2, max = 20) String nickname,
    @NotBlank @Size(min = 2, max = 20) String avatarId
) {}

8实体与跨库时间列

JPA 实体用 @Entity/@Table/@Id/@Column。@JdbcTypeCode(SqlTypes.VARCHAR) 把 UUID 当 VARCHAR 存（让 PG 与 SQLite 一致）；复合主键用 @Embeddable + @EmbeddedId。

OffsetDateTimeStringConverter：SQLite 没有原生时间类型，用 TEXT 存。这个全局 @Converter(autoApply = true) 写入时把 OffsetDateTime→Timestamp(UTC)、读出时还原。autoApply=true 让所有实体的 OffsetDateTime 字段自动经过它，业务代码不感知。这是双库三解法里的「A 类 · 类型层挂适配器」。

9Spring Data JPA：写接口，框架生成 SQL

继承 JpaRepository<T, ID> 就自动拥有 save/findById/findAll/delete/count。方法名即查询：findByEmail → SELECT … WHERE email = ?。三种进阶写法：

@Query · JPQL

操作「实体名」而非表名。findPlazaPage 用命名参数 + Pageable，Spring 自动加 LIMIT/OFFSET 并执行 count，包成 Page（页码从 0 开始）。

@Modifying · 原子 UPDATE

set favoriteCount = favoriteCount + 1，配 flushAutomatically/clearAutomatically。用原子 UPDATE 而非「load → +1 → save」让并发收藏不丢计数。

@Lock · 行锁

@Lock(PESSIMISTIC_WRITE) 对应 SELECT … FOR UPDATE。Postgres 路径用它串行化并发收藏；SQLite 单写事务本身足够。

10服务层与 refresh 轮转

控制器薄，业务都在 service/。refresh 是最复杂的一段，关键是声明式事务流派：

@Transactional(noRollbackFor = ApiException.class)
public AuthTokens refresh(...) {
  // 默认 unchecked 异常会触发回滚，但「重放检测时把整族 revoke 然后抛 401」
  // 需要把 revoke 的写入提交掉，所以告诉 Spring 别为 ApiException 回滚
  ...
  if (row.revokedAt != null) { revokeFamily(...); throw ApiException.unauthorized(...); }
}
这是事务四流派里的「① 声明式」——直接 throw，靠 noRollbackFor 保证吊销不被回滚。其余手写事务的后端（Gin/Ktor/…）用 outcome 枚举模拟这一行为，注释还互相点名 noRollbackFor。其它服务：AvatarService 用 @PostConstruct 在 bean 初始化后缓存头像目录；LlmClientService 用 JDK HttpClient 先试 /responses 失败再退 /chat/completions，两层降级失败用本地模板兜底。

11测试：SmokeTest

@SpringBootTest(RANDOM_PORT) 启动完整容器 + 内嵌 Tomcat 监听随机端口，TestRestTemplate 发 HTTP。端到端 smoke：注册 → 创建胶囊 → 校验未到点 content 为 null → 第二用户收藏 → 校验 hot 排序 → refresh 轮转后旧/新 token 都被废（重放检测）。覆盖 spec 最关键的不变式（I2 计数一致、I3 到点前不可见、refresh 一次性）。
