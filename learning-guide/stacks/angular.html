1技术选型与设计特色

Angular 19 · 企业级架构

强大的 DI 系统 + 模块化服务 + 独立组件（Standalone），业界最严谨的架构范式。

Angular Signals · 细粒度响应式

原生集成 Signals，细粒度依赖追踪实现模板与数据的精准重绘，告别 zone.js 暴力脏检查。

NgRx Signal Store

内置生命周期钩子 onInit 自动水合，比 React/Vue 的手动触发更优雅。

TypeScript 一等公民

装饰器元数据、模板类型检查、input.required<T>() 都用了 TS 类型，几乎不可能裸 JS。

2Angular 的五个核心概念

① 装饰器 + 元数据

@Component({selector, template, imports}) 编译时把元数据附在类上，CLI 读取生成执行代码。@Injectable/@Input/@HostListener/@ViewChild 同理。

② 依赖注入 inject()

全局 DI 容器，@Injectable({providedIn:'root'}) 全应用共享一个实例，组件 inject(...) 取用。必须在 injection context（构造/字段初始化）里调用。

③ Signals 响应式

见 §3——读是函数调用 count()，写用 .set()/.update()，细粒度更新。

④ 模板绑定

[src] 属性绑定、(click) 事件、[(ngModel)] 双向（需 imports:[FormsModule]）。

⑤ 新控制流 @if / @for / @switch

见 §4——逐步替代旧的 *ngIf/*ngFor，可读性强很多。

DI vs import：DI 让单元测试可「换掉」某服务（mock 替换真 ApiService），还允许不同作用域提供不同实例。对照表：拿状态 useAuthStore()(React/Vue) → inject(AuthStore)(Angular)；拿 API import { api } → inject(ApiService)。

3Signals：Angular 17+ 的细粒度响应式

const count = signal(0);
console.log(count());              // ← 像调用函数一样读值
count.set(5); count.update(c => c + 1);    // 写
const doubled = computed(() => count() * 2);   // 派生，依赖自动追踪
effect(() => console.log(count()));            // 副作用，依赖变化就重跑
与其他栈的读值语法差异：Angular 是函数调用 count()，Vue 是 count.value，React 是直接值。模板里也直接调函数：[disabled]="busy()"、@if (auth.user(); as user)。这是响应式模型谱系里「虚拟 DOM + Signal 自动追踪」的代表。本项目统一用新版 input()/output()/signal()，对 zoneless 友好。

4新控制流 @if / @for

@if (loading() && items().length === 0) {
  <div class="cy-empty">加载中…</div>
} @else if (!loading() && items().length === 0) {
  <ng-content select="[empty]" />
} @else {
  <div class="cy-grid">
    @for (c of items(); track c.id) {        <!-- track 对应 React/Vue 的 key -->
      <app-capsule-card [capsule]="c" />
    }
  </div>
}

看起来像 JS 控制流，可读性比 *ngIf/*ngFor 强很多；@for 必须有 track；@if (...; as user) 是绑定别名（if + 局部变量）。内容投影用 <ng-content select="[empty]">（对应 Vue 具名 slot、React children）。

5路由：懒加载 + 函数式守卫

唯一默认做路由级懒加载的栈：loadComponent: () => import(...).then(m => m.XxxComponent)——初始 bundle 不含冷门页面，访问时才下载（也是它 dist 里那么多 chunk 的来源）。守卫是函数：

export const authGuard: CanActivateFn = (_route, state) => {
  const auth = inject(AuthStore);
  const router = inject(Router);
  if (!auth.hydrated()) return true;                       // 水合前放行
  if (auth.user() || auth.refreshToken()) return true;
  void router.navigate(['/login'], { state: { from: state.url } });
  return false;
};

6数据层：ApiService（可注入服务）

唯一把 fetch 封装成可注入 @Injectable 类的栈（其余四栈用自由函数）。逻辑与 React/Vue 版完全一致——refreshing 单例去重、_retry 防死循环。

Angular 不需要 configureApi 注入回调破循环依赖——但本实现仍用 api.configure({...})（由 AuthStore 的 onInit 主动调），刻意与 React/Vue 同构。这也是 Angular 共享逻辑层只有 472 行（少 57 行）的原因：它把「注入回调」换成了「注入服务」。刻意用原生 fetch 而非 HttpClient，让五栈 API client 核心算法逐行对应阅读。

7HttpClient + Interceptor 对照（取舍）

评审最大缺口：HttpClient + interceptor 恰是 Angular 网络层的看家惯用法，auth/refresh 拦截器是其最经典的教学场景，本实现砍掉了它。手册用一整章给出对照写法：

本项目（原生 fetch）HttpClient + Interceptor
返回类型Promise<T>Observable<T>
Auth headerrequest<T> 内部手写拦截器统一注入
401 处理条件判断 + 递归重放catchError + switchMap
公开端点标记opts.auth: falseHttpContextToken
请求取消AbortController 手写takeUntilDestroyed() 自动
跨栈对比可读性✅ 与四家逐行等价❌ 需先懂 RxJS

选 fetch 的理由：一旦换成 RxJS 管道，「React 的 client.ts 与 Angular 的 api.service.ts 并排读」的对比价值就消失了，差别只剩「函数模块 vs 可注入 class」。真实 Angular 项目里 HttpClient + Interceptor 是更正确的方向。

8NgRx Signal Store

signalStore({providedIn:'root'}, withState(...), withMethods(...), withHooks(...)) 是工厂函数，组合多个「feature」生成 @Injectable 类。状态字段自动暴露为 signal（store.items()），写入用 patchState(store, partial)（不能 store.items = ...）。

withHooks.onInit 是 Angular 最优雅之处：store 首次被 inject 时自动触发，在里面 api.configure({...}) + store.hydrate()。对比 React 写在模块顶层、Vue 要 wireAuthApi() 显式触发——Angular 由 DI 容器自动触发，使用方完全无感。跨 store 联动 plaza.patchFavorited(...)、序列号守卫 let fetchSeq = 0 与五栈同构。
