1技术选型与设计特色

Next 15 App Router

文件系统路由；页面/API 同进程，省去 CORS。

React 19 · RSC + 客户端孤岛

公开读页在服务端取数渲染，交互组件按需 "use client"。

Drizzle ORM · 双 schema

PG / SQLite 两套 schema，类型安全查询，mode: "string" 让 timestamp 两库类型同构。

server-only 编译期防火墙

services/*、db/*、lib/server/* 顶部 import "server-only"，误引入客户端组件会在 next build 阶段报错。

2双入口架构：一个进程，两套接口

App Router 核心约定是文件夹即路由，特殊文件名表达角色：

文件角色例子
page.tsx这条 URL 对应的页面app/login/page.tsx → GET /login 返回 HTML
layout.tsx子树共享的布局壳app/me/layout.tsx 包住 /me/*
route.ts这条 URL 的 REST 端点app/api/v1/health/route.ts → 导出 GET 函数
[code] 文件夹动态路由参数app/c/[code]/page.tsx → /c/AB12CDEF
没有路由配置文件——src/app/x/y/z/page.tsx 就是 /x/y/z。一个 route.ts 里可以 export GET / POST / PATCH / DELETE 并存。这是全栈双入口在 Next 里的形态。

3Server vs Client Component

Server ComponentClient Component
标记（默认）文件顶部 "use client"
运行在只在服务端SSR 一次 + 浏览器 hydrate 后接管
useState/useEffect❌✅
import 数据库✅ 直接读❌
async function Page()✅ 顶层 await❌
打包进 JS bundle❌ 不进✅ 进
RSC 不是摆设：广场页 / 胶囊详情页是 async function Page()，直接 import 服务层 plazaList() 取数——零 HTTP 开销，调用链 page.tsx → services/plaza.ts → db → Drizzle → DB，首屏 HTML 已含数据、无 loading。PlazaToolbar 是 "use client" 孤岛，用户操作改写 URL，触发 Next 向服务端发新 RSC 请求重新查 DB。登录/创建/「我的」仍是 Client Component + /api/v1/*，与 SPA 保持一致便于对比。这是边界谱系最左端「边界模糊」的代表。

4server-only 编译期防火墙

// src/services/auth.ts
import "server-only";   // 如果有客户端模块 import 这个文件，构建直接报错

services/*、lib/server/*、db/* 全部首行加——保证数据库连接、JWT 密钥、bcrypt 绝对不会被打进浏览器 bundle。如果某 Client Component 不小心 import { login }，next build 会失败并指出问题文件。这是构建期保证，比手动管理「哪些代码安全发到客户端」可靠得多。

5RSC + httpOnly cookie 识别用户

问题：RSC 在服务端执行，浏览器不会自动带 Authorization: Bearer 头（那是客户端 JS 行为），而 access token 存在 localStorage，服务端读不到。如何让服务端知道「当前请求是谁」？

方案：登录/注册/刷新 Route Handler 返回 JSON 的同时，额外写一枚 httpOnly cookie ht_session。浏览器每次同源请求（包括 GET / 普通页面）自动携带，RSC 用 getServerViewer() 读取解码。

调用方鉴权方式在哪里
浏览器客户端 JS（SPA 页）Authorization: BearerrequireClaims(req) in Route Handler
RSC 服务端渲染ht_session httpOnly cookiegetServerViewer() in page.tsx

httpOnly 意味着客户端 JS 无法通过 document.cookie 读到——XSS 无法直接窃取。这是cookie→身份桥在 Next 的写法（其余四栈在更外层用 Filter/中间件翻译）。

6Drizzle 双数据库

db/index.ts 按 DB_DRIVER 动态 import()（SQLite 模式不加载 pg，反之亦然）；用 globalThis.__helloTimeDb 单例跨 HMR 保留连接（dev 模式 HMR 重新执行模块会建死连接）。Schema 用 TS 对象描述表，Drizzle 自动推导类型；schema-pg.ts 与 schema-sqlite.ts 字段同名同含义、仅类型映射不同。这是全栈跨库里的「双 schema + 动态驱动」。

addFavorite/removeFavorite 在注释里明确写了「教学版接受非原子计数」——没有用 BEGIN/COMMIT 显式事务。这是与 FastAPI/Spring Boot 参考实现的有意差别（next/nuxt 文档化了「不做事务的原因」，三家 MPA 全栈则给出生产级行锁做法，两边互为教学参照）。

7withApi 与三段式

每个 Route Handler 都是 route.ts (HTTP) → services/*.ts (业务) → db/* (数据) 三段式。withApi 统一响应包装：成功套 {success:true, data}、失败（ApiError 或未捕获异常）套 {success:false, message, errorCode}。业务代码只管 return data 或 throw ApiError.notFound(...)，不直接构造 Response——与 FastAPI 的 ApiException + 全局异常处理器异曲同工。

8全栈 vs SPA + 独立后端

维度SPA + 独立后端Next.js 全栈
进程两个（FastAPI + Vite）一个（Next :7177）
跨域需要 CORS / vite proxy同源，无 CORS
类型共享前端手写 TS 对应 Python schema可共享 Zod schema
DB 连接后端持有server-only 防火墙保证不泄露
「直接读 DB」前端不可能RSC 广场/胶囊页已实现
