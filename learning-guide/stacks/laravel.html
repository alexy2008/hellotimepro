1选型与双入口

同一进程两套接口：/api/v1/*（契约测试 + 浏览器 fetch，Bearer 或同源 cookie，JSON envelope）和 Web 页面（浏览器导航/表单，httpOnly cookie，Blade HTML）。routes/web.php 定义 SSR 页面，routes/api.php 定义 REST 契约。API 与页面共享同一套 Service，避免 JSON 行为和页面行为分叉。

2Laravel 的核心思想

路由表显式集中

JSON API 和 Web 页面在同一个地方看清边界，不混在组件树里。

Blade 是服务端模板

服务端拿到数组数据后直接输出 HTML。校验/权限/收藏计数/分页查询都在服务层。

Alpine.js 轻量浏览器状态

没引入 Vue/React、没把页面变成 SPA。适合服务端渲染的留 Blade，即时状态交给 Alpine。

创建胶囊体现「页面与 API 共用服务」：POST /api/v1/capsules 与 POST /create 都落到同一个 CapsuleService::createCapsule()。

3Eloquent ORM（招牌特性）

数据访问全部走 Eloquent——Laravel 最具代表性的特性，本实现刻意用它体现框架价值：

  • 模型：app/Models/{User,Capsule,Favorite,RefreshToken}.php
  • 关系：Capsule belongsTo owner、hasMany favorites；列表查询用 with('owner') 预加载避免 N+1
  • 查询构建器：Capsule::query()->where(...)->orderByDesc(...)->forPage(...)->get()；搜索用 whereHas('owner')；计数用 increment/decrement；并发用 lockForUpdate() + DB::transaction()

4跨库两个关键取舍（全栈版比纯后端更刁钻）

取舍一 · id 与时间戳不做 Eloquent Cast：在模型里保持存储格式。因为关系 join 和 where 用的是原始存储值——若把 id Cast 成带横线 UUID，SQLite（存 32-hex）的关系关联会失配。转换只在输出边界（Mapper）做、入参在查询边界用 CrossDb 归一。这是「id 为什么不能被 ORM 强类型化」的真实案例。
取舍二 · 布尔用自定义 Cast CrossDbBoolean：不能用 Eloquent 原生 boolean Cast——PDO pgsql 把 boolean 读回成 't'/'f' 字符串，而原生 Cast 等价 (bool)'f' 竟为 true，会把「未公开」误判成「公开」。自定义 Cast 读时显式归一、写时按驱动产出 0/1 或 'true'/'false'。
还有一处：列表/详情查询都加 has('owner')，把 owner 已被级联删除的「孤儿胶囊」排除（复刻裸 SQL 的 INNER JOIN 语义，否则 with('owner') 会带 null owner 进 Mapper 触发 NPE）。主键不是自增整数：HasCrossDbKey trait 设字符串主键、creating 钩子按驱动生成存储格式 id。

5鉴权与「为何不用 auth middleware」

API 契约要 Bearer，SSR 页面用 httpOnly cookie，AuthService::currentUser() 双读：契约测试带 Bearer，浏览器登录后写 ht_access/ht_refresh cookie，同源 fetch 自动带 cookie。

刻意不用 Laravel auth middleware / FormRequest，而在控制器里手工 $this->auth->requireUser($request)。理由：① 跨栈同构——五个全栈的 API 端点都用「控制器里显式鉴权」，读者可并排读；② 鉴权逻辑可见——public vs protected 一眼从 requireUser vs currentUser 看出，不用查中间件列表；③ 教学规模——只有一个 Controller、不到 30 端点。真实规模项目建议走 guard + middleware。

6收藏与搜索焦点守卫竞态

FavoriteService 在 DB::transaction() 里用 Eloquent 维护：lockForUpdate() 锁行 + 检查 + Favorite::create() + increment('favorite_count')；取消用幂等 delete() + where('favorite_count','>',0)->decrement()（>0 守卫钳下限）。收藏按钮用 Alpine 异步 fetch（与 Spring/Rails 的同步 /ui/* 不同）。

一处真实竞态：收藏测试「点完立刻 goto('/me/favorites')」曾在 PG 偶发 net::ERR_ABORTED。根因不在收藏层，而在广场搜索框：@input.debounce.300ms 触发整页 form.submit()，这个迟到的导航与测试随后的 goto 相撞。修复是给提交加焦点守卫 document.activeElement === $el && $el.form.submit()——只在搜索框仍持有焦点时才提交。既消除竞态，也是更合理的实时搜索 UX。

7Blade + Alpine + 原生 fetch

layouts/app.blade.php 公共布局；Blade components（capsule-card/pagination/me-nav）承担复用（对应 Next/Nuxt 的 components，只是渲染在服务端）。public/js/app.js 注册 Alpine data/store（theme/countdown/favButton/codeInput/createCapsule/profileEditor/avatarPicker…），不保存 access token（token 在 httpOnly cookie，fetch 自动带）。Alpine 被复制到本地 public/js/alpine.min.js，避免运行时依赖 CDN。
