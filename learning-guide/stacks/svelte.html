1技术选型与设计特色

Svelte 5 + svelte-routing

Runes 通过编译期静态分析实现无虚拟 DOM 的极致运行效率与精确重绘。

Runes Class Singletons

摒弃状态管理库，直接用 $state 在标准类中声明响应式状态，以模块化 class 单例暴露全局状态。

Vite · 极薄产物

完美对接 Svelte 编译流程，生产环境输出极其轻量的静态资源（仅 svelte + routing 两个运行时依赖）。

设计令牌 + Tailwind v4

跨前端通用 CSS 变量，暗/亮主题切换高效。

2Runes 核心概念

Runes 是一套以 $ 开头的特殊语法，用于声明响应式状态、副作用和推导值——Svelte 5 与旧版最大的区别，也是与 React Hooks、Vue Composition API 最直接的对标。

$state 响应式状态

直接 count++ 就触发更新（编译期把赋值变成通知）——无需 React 的 setCount、无需 Vue 的 .value。对象/数组递归代理，可直接 items.push(x)。

$derived 推导值

等效 Vue computed、React useMemo，自动追踪不需依赖数组。复杂用 $derived.by(() => {...})。

$effect 副作用

自动追踪函数体里读到的 $state，返回函数即清理。untrack() 圈住不想追踪的读取。

$props 接受父值

let { capsule, size = "sm" }: Props = $props()，统一解构 + 默认值。在 .svelte.ts 里不能用，用普通函数参数。

3Snippet：Svelte 5 取代 slot 的新原语

<!-- 父：定义 snippet 内容 -->
<CapsuleGrid {items}>
  {#snippet empty()}<p>暂无数据</p>{/snippet}
  {#snippet card(c)}<button onclick={() => withdraw(c.id)}>撤回</button>{/snippet}
</CapsuleGrid>

<!-- 子：渲染 snippet -->
{@render empty?.()}
{#each items as c}{@render card?.(c)}{/each}

Snippet 等效 React 的 render prop / slot。本项目用 empty 和 card 两个 snippet 自定义 CapsuleGrid 的空态和每张卡片右侧操作区。children 也是内置 snippet prop（{@render children()} 等效 React children）。

4扁平路由（招牌坑）

svelte-routing 2.13 + Svelte 5 要求路由扁平化，不能嵌套 <Route>。嵌套会触发 effect_update_depth_exceeded（子 Route 注册 → 触发父 Route 重渲染 → 子 Route 再注册 → 无限循环）。解决方案：每个 Route 直接内联自己的布局组件，而非靠 Router 的嵌套机制注入 Outlet。
<Router>
  <Route path="/"><MainLayout><PlazaPage /></MainLayout></Route>
  <Route path="/me/created"><MeLayout><AuthGate><MeCreatedPage /></AuthGate></MeLayout></Route>
  <Route><MainLayout><NotFoundPage /></MainLayout></Route>  <!-- 兜底 -->
</Router>

跳转：<a href="/login" use:link>（action 阻止默认、走前端路由）或编程式 navigate("/login")。路径参数用 let:params 注入。

5.svelte.ts class 单例

与 Zustand/Pinia 不同，Svelte 5 允许把 $state 写在普通 class 字段上，仪式感最少：

class AuthStore {
  user = $state<User | null>(null);
  refreshToken = $state<string | null>(null);
  hydrated = $state(false);
  hydrate() { const p = load(); if (p) { this.user = p.user; ... } this.hydrated = true; }
}
export const authStore = new AuthStore();   // 模块级单例

export const authStore = new AuthStore() 是模块级单例，所有组件 import 拿到同一实例，等效 Zustand 全局单例。跨 store 联动 plazaStore.patchFavorited(...)、序列号守卫 用私有字段 #fetchSeq（因为 store 是 class 实例）。

6关键陷阱：.svelte.ts 必须带 .ts 后缀导入（必读）

import { authStore } from "@/stores/auth.svelte.ts";   // ✅ 正确
import { authStore } from "@/stores/auth.svelte";      // ❌ 破坏单例
原因：@sveltejs/vite-plugin-svelte 处理 auth.svelte 时，会同时把它当「Svelte 组件」和「TS 模块」两条加载路径解析，产生两个不同的模块实例。authStore 在 A 实例里 hydrate，但 AppHeader 读的是 B 实例（没有 user）——store 单例彻底破裂。带 .ts 后缀后 Vite 只走 TS 模块路径，始终一个实例。tsconfig.app.json 的 allowImportingTsExtensions: true 就是为支持这个写法。这是前端招牌坑里 Svelte 的代表坑。

7Runes 工具库（lib/）

createCountdown

$state now + $effect setInterval，active 是函数（effect 需每次读最新状态决定是否追踪）。已开启不创建 interval。暴露 getter 而非直接暴露 state。

createDebounced

$effect 追踪 source + setTimeout，PlazaToolbar 搜索框 300ms 防抖用。

clickOutside（action）

Svelte action 是「DOM 生命周期的副作用函数」：挂载时调用、卸载时调 destroy()。比 $effect 手动 addEventListener 更封装。

8数据层与 wireAuthApi

api/client.ts 与 React/Vue 版几乎逐字一致：通用 request<T> + 自动 refresh（refreshing 单例去重 + _retry 防死循环）。不 import store（否则 auth.svelte.ts → client.ts → auth.svelte.ts 循环），用 configureApi 依赖注入，wireAuthApi() 在 main.ts 的 mount() 前调用一次。
