1选型与双入口

同一进程提供两套入口：/api/v1/*（契约测试 + 浏览器 fetch，Bearer 或 cookie→Bearer 桥，JSON envelope）和 SSR 页面 + /ui/*（浏览器导航/Turbo/Stimulus，httpOnly cookie，ERB HTML / Turbo Stream）。config/routes.rb 同时定义三者；API 控制器继承 ActionController::API 只返回 JSON，页面控制器继承 ApplicationController 用 ERB 渲染。

2Rails + Hotwire 的核心思想

路由集中 + Controller 命名约定

Next/Nuxt 用目录表达路由，Rails 用 config/routes.rb 显式声明，再按 controller/action 分发。查 URL 先看 routes 再看 controller。

ERB 是服务端输出 HTML

页面控制器准备实例变量（@items/@pagination），ERB 直接渲染。业务规则不放视图里。

Turbo = HTML 局部协议

局部更新也由服务端渲染成 HTML，浏览器直接换进 DOM，不在客户端用 JSON 重渲染。

Stimulus 只管小交互

不引入 SPA store：需要持久化的状态在服务端，需要即时响应的交给 Stimulus。

5CookieTokenBridge：Rack 中间件桥

若 PATH_INFO 以 /api/v1/ 开头 且 HTTP_AUTHORIZATION 为空 且 Cookie 中有 ht_access
则设置 HTTP_AUTHORIZATION = Bearer <ht_access>
浏览器同源 fetch /api/v1/me 不需要 JS 读取 token 也能复用 API 控制器；契约测试带真实 Bearer 时中间件不介入。CookieAuth concern 不会每次导航都 refresh，避免 refresh token 重用检测误伤正常会话。这是cookie→Bearer 桥的 Rack 中间件写法（对应 Spring 的 Servlet Filter、Laravel 的 Service 双读）。

6收藏为何用同步 XHR

UI 冒烟有「点收藏后立刻导航到 /me/favorites」的路径。异步 fetch 可能被导航中止，或还未提交就被下一页 SSR 查询抢先读到。favorite_controller.js 对已登录收藏按钮用同步 XMLHttpRequest 调 /ui/capsules/{id}/favorite-toggle，等事务提交后再返回。匿名点击在客户端 confirm 后跳登录。这与 Spring MVC 同源（收藏同步 XHR）。

7Active Record + CrossDb

app/lib/cross_db.rb 处理 PG 与 SQLite 差异：SQLite id 存 32 位无横线 hex TEXT、时间戳存 ISO-8601 TEXT；PG 用原生 uuid + timestamptz；API 输出统一带横线 UUID 和 ...Z。自定义类型 CrossDb::SqliteUuidType / SqliteTimestampType 对应 Spring 的 Hibernate JdbcType、Laravel 的 CrossDb。

数据层注释教学价值最高：FavoriteService 在事务里维护计数——锁胶囊行（PG SELECT … FOR UPDATE，SQLite 依赖单写事务）→ 禁止收藏自己/未公开 → 插入后递增/删除后递减。非法 UUID 宽松解析为 nil，由调用方转 404，避免数据库类型错误变 500。冒烟测试固定跨库存储格式不变式（小数秒去尾零、uuid↔hex 往返）——量少但每条都是真坑的回归保险。
