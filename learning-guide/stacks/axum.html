1技术选型与理由

维度选择理由
Web 框架Axum 0.8Tokio 官方生态；extractor 模型干净；IntoResponse 让错误处理变成类型问题
数据访问sqlx 0.8（不用宏）契约要求同一套 SQL 跑双驱动，query! 宏的编译期检查绑定单一 DB，故用运行时 sqlx::query + 自研编解码层
JSONserde_json::ValueValue::Null 序列化为显式 null，契约 strict equal 天然满足
JWT手写 HS256（hmac + sha2）签发/校验各 ~20 行；引 jsonwebtoken crate 反而要适配它的 claim 模型
为什么不用 sqlx::Any？Any 驱动的类型推断有限，PG 的 uuid/timestamptz 列用文本协议绑定需要在 SQL 里逐处 ::uuid 强转，SQL 文本就不再是「一份」。自研 Value/Cell 编解码层把差异收敛到绑定/读取两个点，SQL 完全共享。

2整体地图与请求流向

Tokio 运行时 + Axum Router（.fallback() 兜 404）→ handler（async fn，extractor 提参 State / HeaderMap / Result<Json<T>, JsonRejection> / Query）→ services（async fn → ApiResult<Value>，db.begin() → 业务 → conn.finish(result)）→ repos → db.rs（一份 SQL，? 占位 PG 转 $n，Value 绑定 / Cell 读取）→ PG（池 8）或 SQLite（池上限 1，天然串行）。

3Rust / Axum 的三个核心机制

机制一handler = async fn + extractor 提参

参数是一组 extractor，Axum 按类型从请求里提取。三个关键约定：① 请求体 DTO 字段全 Option（缺字段不在解码层失败，由 validation 统一裁决 422）；② 查询参数用 Query<HashMap> 手动解析（int_param 区分缺失→默认、非整数→422）；③ axum 0.8 路径语法是 {param}。

机制二Arc<AppState> 共享、Send + Sync 是硬约束

AppState 用 Arc 包起注入每个 handler，跨 await 点共享。Rust 要求跨 await 的状态满足 Send + Sync——这就是为什么 LoginRateLimiter 用 Mutex<HashMap>、Db 内部用连接池：编译器强制你把共享可变状态做成线程安全的，否则不编译。

4机制三 · ? + IntoResponse：错误处理变成类型问题

ApiError 实现了 IntoResponse，所以返回 ApiResult<Response> 的 handler 里，任何 ? 都直接产出契约错误外壳：

impl IntoResponse for ApiError {
    fn into_response(self) -> Response {
        envelope::error(self.status, self.code, &self.message, self.details.as_deref())
    }
}
「漏接异常」在 Rust 里编译不过——Result 不处理就有警告/类型不符，service 里 repo(...).await? 一路把 ApiError 冒泡到 handler，由 Axum 调 into_response()。与 Vapor 的「中间件 catch 转换」对照：那边是运行时兜底，这边是类型系统直接表达，没有「忘了捕获」的可能——这是十家里把「语言特性当正确性保障」展示得最彻底的。

5Value / Cell 跨库层（本实现的核心）

业务 SQL 用 ? 占位写一份，PG 执行前 to_pg_placeholders 顺序替换为 $1..$n。差异收敛在绑定与读取两个枚举：

绑定：Value 枚举

Uuid(u)PG 原生 / SQLite 32-hex TEXT
Ts(t)PG timestamptz / SQLite ISO TEXT
Bool(b)PG boolean / SQLite 0/1

读取：Cell 枚举 + DbRow 访问器

访问器是 cell-driven 而非 driver-driven：row.uuid("id") / row.ts("open_at") / row.bool("in_plaza")，仓储代码不需要知道自己跑在哪个库上。

两边解码的不对称值得理解：PG 侧列类型信息完整，解码时就把 UUID/TIMESTAMPTZ/BOOL 分别还原成 Cell::Uuid/Ts/Bool；SQLite 侧只有 INTEGER/REAL/TEXT 三种存储类，统统落进 Cell::Str 或 Cell::I64，再由访问器按目标类型反解。同一行在两个库里 Cell 形态不同，但访问器把差异收口在读取这一点。按「值的实际存储类」而非「列声明类型」分发——因为 COUNT(*)、(x IS NOT NULL) 这类表达式列在 SQLite 里没有可靠的声明类型。这是双库三解法的「C 类」。

6事务与一致性

事务不走 sqlx 的 Transaction 类型（它会让连接类型在 enum 两臂分叉），而是显式 BEGIN/BEGIN IMMEDIATE + conn.finish(result)：

let mut conn = state.db.begin().await?;
let result = async { /* 多步操作，可 ? 提前退出 */ }.await;
conn.finish(result).await    // Ok → COMMIT，Err → ROLLBACK

纪律：一个 service 公共方法只 acquire 一次连接，绝不同时持有两个（SQLite 池上限 1 会自锁）。收藏计数 UPSERT 判真插入才 +1；refresh 轮转用 RefreshOutcome::{Success,Invalid,Reused}，COMMIT 之后再把 Invalid/Reused 转 401（流派 ③）。

7手写 JWT 与安全

let signing_input = format!("{header}.{body}");
let mut mac = HmacSha256::new_from_slice(config.jwt_secret.as_bytes()).unwrap();
mac.update(signing_input.as_bytes());
let signature = URL_SAFE_NO_PAD.encode(mac.finalize().into_bytes());

校验顺序：形态 → 签名（mac.verify_slice，常数时间）→ payload → exp。过期返回 access_token_expired。bcrypt 用 bcrypt crate（cost 10），$2b$ 与 seed 互验。Rust 特有：regex crate 不支持 lookahead，密码的 (?=.*[A-Za-z])(?=.*\d) 改为显式扫描；长度按字符（chars().count()）不按字节。
