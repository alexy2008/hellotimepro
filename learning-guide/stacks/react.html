1技术选型与设计特色

React + React Router · 声明式 SPA

声明式 UI + 单向数据流，配合嵌套路由与守卫。切换页面无需刷新浏览器。

TypeScript · 契约对齐

静态类型让前端数据结构与后端 OpenAPI 契约高度一致，编写阶段即拦截字段拼错、未处理 null。

Vite · 极速 HMR

基于原生 ESM 的热更新，改动即时响应；生产输出高度优化的静态资源。

Zustand · 轻量解耦状态

避开繁重 Redux，模块化单例 + 订阅既避免 Context 无谓重渲染，又极易在组件外部（API 客户端）同步读写状态。

2一次「打开广场页」的流向

浏览器 GET / → 返回 index.html（仅一个 <div id="root">）
↓
main.tsx：createRoot(...).render(<App/>)
↓
App.tsx：useEffect 调 hydrate auth/theme → 渲染 <RouterProvider/>
↓
router.tsx 按 URL 匹配 → <MainLayout><PlazaPage/></MainLayout>
↓
PlazaPage 的 useEffect 调 usePlaza.fetch() → fetch("/api/v1/plaza/capsules")
↓

只有状态变更会触发渲染，没有人手动操作 DOM——这是 React 和原生 JS 写法最大的差别

3React 的四个核心概念

① 组件 = 返回 JSX 的函数

大写开头的函数返回 JSX。用 <AppFooter/> 而非 AppFooter()——这是给 React 看的标记，让它把函数纳入虚拟 DOM 树。

② JSX = HTML-in-JS

class→className、for→htmlFor、onClick={fn}、style={{}}。条件/列表都是普通 JS（三元 / && / map）。列表项必须给稳定 key，不用 index。

③ Props = 参数；State = 记忆

单向数据流：父用 props 传值，子用回调影响父。State 用 useState——因为组件每次渲染从头执行，let 会被重置，useState 让 React 在组件实例外保留值并在 set 时触发重渲染。

④ Hooks：钩入框架能力

以 use 开头，只能在组件顶层调用（React 靠调用顺序辨认）。useState/useEffect/useRef/useMemo + 自定义 Hook（Zustand store）。

函数式更新避免闭包陷阱：setInterval(() => setTick(x => x + 1), 1000) ✅ 拿到最新值；setTick(tick + 1) ❌ tick 永远是 effect 那次的快照。这是 React 里最常踩的坑之一。核心心智：UI = f(state)，你永远不直接 document.getElementById(...).innerText = ...。

4路由与守卫

createBrowserRouter data router + 布局嵌套路由（父只给 element 无 path，子页面渲染到 <Outlet/>）。守卫是组件：

export function AuthGate({ children }) {
  const { user, hydrated, refreshToken } = /* 从 store 读 */;
  if (!hydrated) return null;                          // 等 localStorage 读完
  if (user || refreshToken) return <>{children}</>;     // 已登录或可静默续期
  return <Navigate to="/login" replace state={{ from: location.pathname }} />;
}
守卫的精妙：只要 refreshToken 在就放行——接下来的 API 调用会自动 refresh，用户看不到打断。这个「乐观放行 + 惰性续期」由共享逻辑层的自动 refresh 赋予。五栈守卫对比 →

5数据层与自动 refresh

通用 request<T>(path, opts)：自动拼 Authorization、序列化 body、解开统一外壳 {success,data,message,errorCode}（调用者只看到 data）、失败抛 ApiError、204 直接返回。

模块级单例 refreshing：一波 401 同时发生时只发一次 refresh，其余 await 同一个 Promise；_retry 防死循环
与 store 解耦：api/client.ts 不 import { useAuth }（否则与 stores/auth.ts 形成循环）。用依赖注入 configureApi({ getAccessToken, onAuthLost })——store 模块加载时注册一次。这是前端共享逻辑层「破循环依赖」的四栈通用招（Angular 靠 DI 不需要）。

6状态层 Zustand

create((set, get) => ({...}))：set 浅合并触发订阅者重渲染，get 同步读。useAuth 本身是自定义 Hook，组件用选择器细订阅（useAuth(s => s.user)，只在 user 变化时重渲染——选越细性能越好）。也能在组件外 useAuth.getState() 同步读。

Store关心什么持久化
useAuthuser / accessToken / refreshToken / hydratedrefreshToken + user → localStorage
useThemedark / lightlocalStorage
usePlazasort / filter / q / page + items / pagination否
useCapsulemine / favorites 两个分页列表否
跨 store 联动：useCapsule.toggleFavorite 收藏成功后直接调 usePlaza.getState().patchFavorited(...) 同步广场列表——从「我收藏的」取消后切回广场，那条不会还显示已收藏。Zustand store 是模块级单例，.getState() 同步读不通过 React 订阅，所以互相 import 不破坏渲染。

7倒计时与序列号守卫

倒计时（React 特有写法）：状态变才重渲染，于是造一个无意义的 tick 逼组件重跑、计算放渲染期：

const [, setTick] = useState(0);
useEffect(() => {
  if (opened) return;                                              // 已开启不开定时器
  const t = window.setInterval(() => setTick(x => x + 1), 1000);   // 函数式更新
  return () => window.clearInterval(t);                            // 清理
}, [opened]);
const cd = countdownTo(capsule.openAt);                            // 每次渲染重算
并发请求序列号守卫：快速切 sort/filter 连发多个请求，响应顺序不保证。模块级 let fetchSeq = 0，只有「最新发起」的请求才能写回结果（if (myId !== fetchSeq) return）。五栈用完全相同的思路。

8样式与设计令牌

src/styles/index.css @import spec 的 palette/tokens/cyber.css。spec/styles/tokens.css 是设计系统单一来源，五个前端共用，改一次全生效。主题切换靠 data-theme="dark|light"（index.html 内联脚本尽早设置，避免主题闪白）。组件用 cy-* 共享类，禁止硬编码色值或用色阶变量 --brand-500。
